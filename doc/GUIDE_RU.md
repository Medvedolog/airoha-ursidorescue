# Руководство оператора UrsidoRescue

[English version](GUIDE_EN.md) · [Оглавление](README.md) · версия 0.2.0-test17

## 0. Прежде чем начать

- Это **лабораторная UART-сборка**. Запись во flash на железе пока не прошла полный цикл проверки —
  см. [../STATUS.md](../STATUS.md). Работайте, только если понимаете, что делаете, и у вас есть
  бэкап.
- **Бэкап — главное.** Заводские MAC, серийный номер, GPON-данные и калибровки оптики невозможно
  восстановить без бэкапа (например, снятого MedveFlasher).
- Для чтения и диагностики (пункты 5, 7, эксперт 1/6) ничего не пишется во flash. Пункты 1–3 и
  эксперт 3/4 пишут — перед записью всегда требуется ввести фразу подтверждения.

## 1. Что понадобится

| что | зачем |
|---|---|
| USB-UART адаптер **3.3 В TTL** (CH340, CP2102, FT232 …) | консоль роутера, BootROM, XMODEM |
| 3 провода: **GND, TX, RX** | **VCC не подключать никогда** — роутер питается от своего блока |
| Ethernet-кабель ПК ↔ LAN-порт роутера | TFTP для больших файлов (пункты 1–4, эксперт 3–4) |
| Windows x64 или Linux x86_64 / arm64 | сама программа |
| Бэкап или образ | в зависимости от пункта: `mtd16`, `.fip`, `.itb`, образ NAND 256 МиБ |

**Подключение UART:** TX адаптера → RX роутера, RX адаптера → TX роутера, GND → GND.
Параметры порта (программа выставляет их сама): 115200, 8N1, без управления потоком.

## 2. Установка

1. Скачайте `UrsidoRescue-<версия>.zip` со страницы Releases репозитория и распакуйте.
2. Проверьте целостность: `SHA256SUMS` внутри архива, `.zip.sha256` рядом с архивом.
3. Внутри:

```
UrsidoRescue-0.2.0-test17/
  UrsidoRescue.exe            Windows x64
  UrsidoRescue-linux-amd64    Linux x86_64
  UrsidoRescue-linux-arm64    Linux aarch64 (Raspberry Pi 4/5, ARM-ноутбуки)
  VERSION
  payloads/md/…               preloader и RAM FIP для XG-040G-MD
  payloads/mf/…               preloader и RAM FIP для XG-040G-MF
  STATUS.md  PROBE.md  SHA256SUMS
```

Программа ищет `VERSION` и `payloads/` рядом с собой (до трёх уровней вверх) или в текущем
каталоге. Не перемещайте бинарник отдельно от них. Рабочие файлы и логи создаются в `work/`.

**Linux:** доступ к порту обычно требует группы `dialout` (`sudo usermod -aG dialout $USER`,
затем перелогиниться) или запуска через `sudo`.

**Windows:** при первом запуске Защитник/SmartScreen может предупредить о неподписанном файле.
Для TFTP разрешите входящий UDP-порт **1069** в брандмауэре (или разрешите программе доступ к
частной сети, когда Windows спросит).

## 3. Сеть для TFTP

Нужна для пунктов 1–4 и эксперт 3–4.

- Назначьте Ethernet-адаптеру ПК статический адрес **`192.168.1.254`**, маска `255.255.255.0`
  (любой `192.168.1.x`, кроме `.1`, тоже подойдёт).
- Роутер в RAM U-Boot получит адрес **`192.168.1.1`**.
- DHCP на этом адаптере выключите.
- Кабель — напрямую от ПК к Nokia, в **LAN2 или LAN3**. LAN1 не рекомендуется, LAN4 для
  переходов и загрузки лучше не использовать.
- На время работы **отключите Wi-Fi, VPN, прочие Ethernet, Hyper-V и другие виртуальные адаптеры,
  туннели**. Оставьте только адаптер, подключённый к Nokia.
- Программа сама найдёт адрес `192.168.1.x` на ПК. Если не найдёт — попросит ввести его вручную.
- Встроенный TFTP-сервер слушает `UDP 1069` и отдаёт файл только адресу `192.168.1.1`.
  Отдельный TFTP-сервер не нужен.

Перед каждым мастером с TFTP программа печатает блок **«Сетевые пререквизиты»** с этими
требованиями и список активных IPv4-интерфейсов ПК. Если их несколько, появляется предупреждение.
Работу это не блокирует, но лишние интерфейсы лучше погасить.

Та же сеть нужна для [stock LAN assist](#stock-login) в Porting Collector: там роутер работает
на своей заводской прошивке и отвечает на `192.168.1.1`.

## 4. Как ввести роутер в BootROM

Для всех операций с RAM U-Boot:

1. Выключите роутер.
2. Подключите UART, запустите нужный пункт в программе и дождитесь сообщения
   «Ожидание BootROM Press x / CCC».
3. **Зажмите Reset и подайте питание.** Держите Reset, пока в выводе не появится `Press x`
   (программа сама ответит `x`) и строка `CCC…`.
4. Дальше программа всё делает сама: preloader → FIP → приглашение U-Boot.

Если на экране **уже** `Press x to load BL31 + U-Boot FIP` и бегут `C` — ничего не перезагружайте:
программа поймёт, что preloader уже загружен, и отправит только FIP.

> Не путайте с recovery UrsusBoot: Reset, **зажатый до подачи питания**, — это BootROM Airoha;
> Reset, зажатый **после** старта (2 коротких + 3 длинных мигания), — это recovery-режим UrsusBoot.

## 5. Как передаются данные: XMODEM и LAN/TFTP

<a id="xmodem"></a>
### XMODEM (BootROM и ручная отправка в терминале)

UART-линия у роутеров бывает шумной, а BootROM и следующий этап загрузки ведут себя не как
«учебный» XMODEM. Поэтому правила такие:

- **Ограниченные повторы.** На каждый 128-байтный блок — ожидание ACK до 2 с и **не более 8
  попыток**. NAK или `C` (запрос CRC) — немедленный повтор только этого блока. Между повторами
  80 мс. После 8 неудач — стоп «XMODEM блок N не подтверждён после 8 попыток».
- **ACK важнее шума.** Если в одном чтении UART пришли и мусор `C`/NAK, и ACK — засчитывается ACK.
- **`CAN CAN`, а не `CAN`.** Одиночный байт `CAN` (`0x18`) — это шум линии, он **больше не
  считается отменой**. Приёмник отменил передачу, только если пришло **два `CAN` подряд**: тогда
  стоп «BootROM подтвердил отмену XMODEM (CAN CAN)».
- **`CAN CAN CAN` от ПК — только в фазе данных.** Если передача блоков провалилась, программа
  шлёт три `CAN`, чтобы приёмник не остался в неопределённом состоянии. После ACK последнего блока
  `CAN` не отправляется **никогда**: приёмник мог уже запустить переданный образ.
- **EOT handoff.** После последнего блока отправляется EOT, ответ ждётся 0,9 с:
  - ACK на EOT — передача завершена;
  - NAK — ещё один EOT (только на явный NAK, не более 3 раз);
  - `C` или любой текст — это уже **вывод следующего этапа** (например, `NOTICE: BL31…`); EOT
    больше не шлётся;
  - тишина — EOT **не** повторяется, управление сразу переходит к проверке следующего этапа;
  - **нет ACK на EOT, хотя все блоки данных подтверждены, — само по себе не ошибка.** Успех
    доказывает следующий этап: после preloader — второй приёмник BootROM (`CCC`), после FIP —
    устойчивое приглашение RAM U-Boot. Если этап не появился, срабатывают обычные таймауты
    (до 180 с) и операция останавливается. Байты, пришедшие во время EOT, не теряются — они сразу
    идут в разбор следующего этапа.
- В ручной отправке терминала (Ctrl+] → `s`) при отсутствии EOT ACK выводится «Все блоки XMODEM
  подтверждены; EOT ACK не получен. Проверьте состояние устройства в терминале».

<a id="lan-tftp"></a>
### LAN/TFTP

- **IP ПК по маршруту.** Программа спрашивает ОС, через какой интерфейс идёт маршрут к
  `192.168.1.1`, и берёт его адрес, если он `192.168.1.x`. Запасной вариант — любой активный
  интерфейс с таким адресом. Поэтому при нескольких сетевых картах выбирается та, что реально
  ведёт к роутеру.
- **Сеть U-Boot настраивается один раз за сессию:** временные MAC, `ipaddr`, `serverip`, `netmask`,
  `tftpdstp`, `autoload`. Все следующие передачи и части переиспользуют эти настройки.
- **3 попытки текущей передачи.** Повторяется только текущий файл или текущая 8-МиБ часть; уже
  записанные в NAND части не переписываются.
- **Ресинхронизация U-Boot после сетевого сбоя.** Если сама команда `tftpboot` провалилась:
  - TFTP-сервер останавливается и освобождает UDP/1069;
  - в U-Boot отправляется Ctrl-C до устойчивого приглашения (до 4 циклов по 1,5 с);
  - сетевые переменные задаются заново, затем пауза 1–2 с.
  Если приглашение не вернулось — стоп «не удалось восстановить U-Boot prompt после сетевой
  ошибки».
- **Повтор из-за проверки.** Если `tftpboot` прошёл, но не сошлось число байт или проверка в RAM,
  повторяется только передача — без ресинхронизации и без повторной настройки сети.
- **Проверка в RAM после каждой успешной передачи**, включая повторные: `hash sha256`, если
  есть, иначе `crc32`.
- **Без `ping`.** Потеря ICMP во время поднятия линка и ARP больше не останавливает работу;
  доказательство рабочей сети — сама передача плюс проверка в RAM.
- **Ограниченные ожидания сервера:** запрос RRQ — 30 с, согласование опций — 8 × 1 с, ACK блока —
  10 × 1 с.
- **Windows:** ошибки UDP `WSAECONNRESET`/`WSAECONNABORTED` от «старого» пира считаются шумом и не
  обрывают передачу.

<a id="stock-login"></a>
### Stock LAN assist: вход в stock Linux по UART (Porting Collector)

Касается только Porting Collector на Nokia XG-040G-MD/MF с заводской прошивкой. Stock Linux на
UART спрашивает `Login:`, а пароли сервисных учёток он меняет поздно, в конце загрузки. Поэтому
актуальные реквизиты берутся из штатного Web-интерфейса роутера.

1. Увидев stock `Login:`, probe **не спрашивает логин сразу**. Он печатает «[STOCK] Найден login
   stock Linux; получаю актуальные реквизиты через 192.168.1.1…».
2. До **90 с** ждёт stock Web на `192.168.1.1`, всё это время продолжая вычитывать UART, поэтому
   длинная stock-загрузка не переполнит приёмный буфер порта. Затем:
   - входит в Web штатной учёткой администратора с шифрованием формы;
   - проверяет, что это XG-040G-MD или XG-040G-MF;
   - читает актуальные Telnet- и FTP-реквизиты.
3. Пытается войти по UART **сразу под UID0-сервисной учёткой** (FTP; на MF это `user_ftp`). Если
   serial getty её не пускает — входит Telnet-учёткой (`user-telnet`) и делает `su` на UID0-учётку.
4. Выполняет **`id -u`**. Только ответ `0` считается успехом: «[OK] UART stock shell: UID 0
   подтверждён».
5. Если UID 0 не получен и FTP в stock выключен, задаётся **один вопрос `y/N`**: включить FTP
   через штатную Web UI.
   - Это **изменение stock-настройки** — так и написано в вопросе. FTP останется включённым после
     probe, это отмечается в результате.
   - Raw MTD и прошивка не пишутся.
   - После включения реквизиты перечитываются, вход и `su` повторяются.
6. Если вход получен, но без UID 0, read-only Linux-диагностика продолжается с текущими правами.
   Если stock assist не сработал совсем, probe по-старому спрашивает логин и пароль вручную.

**Повтор после поздней смены пароля.** Доступность Web ещё не означает, что stock init уже
закончил менять сервисные пароли. Если первая попытка не подтвердила UID 0, probe ещё 12 секунд
непрерывно вычитывает UART, один раз перечитывает Web-реквизиты и повторяет вход/`su`. Если FTP
выключен и Web пока не отдаёт FTP-учётку, это не блокирует Telnet-вход и не мешает дойти до
отдельного вопроса о включении FTP. После подтверждённого включения FTP его реквизиты уже
обязательны.

**Безопасность реквизитов.** Пароли хранятся только в памяти. Они не печатаются и не попадают в
bundle, `transcript.jsonl` и `uart.log`: там записывается только метка «password (masked)».
Пароль уходит в UART только после того, как устройство показало `Password:`.

**Командная строка.** Stock assist включается флагом `--stock-lan-assist`; он только читает
реквизиты, FTP из командной строки не включается никогда. Если заданы `--linux-user` /
`--linux-password`, используются они. Если у Web-администратора не заводской пароль, задайте его
переменной окружения `URSIDO_STOCK_WEB_PASSWORD`.

В результате probe отмечаются `linux_uid0`, `stock_lan_assist` и `stock_service_provisioned`
(FTP был включён).

## 6. Запуск

**Интерактивно:**

```
Windows:  двойной щелчок по UrsidoRescue.exe   (или из cmd/PowerShell)
Linux:    ./UrsidoRescue-linux-amd64
```

Открывается полноэкранный интерфейс (TUI). Прежнее текстовое меню — `--console`; оно же открывается само,
если TUI запустить нельзя (ввод или вывод не терминал, `TERM=dumb`, ошибка TUI).

Язык берётся из языка Windows (в Linux — из локали); в TUI его меняет клавиша `l`. Текстовое меню
`--console` спрашивает язык при старте. Задать заранее: `--lang ru|en` (в любом месте командной строки)
или переменная окружения `URSIDO_LANG=ru|en`. Все пункты меню описаны в [MENU_RU.md](MENU_RU.md).

В интерактивном терминале сообщения программы цветные (палитра UrsusBoot/UrsusFlasher).
`NO_COLOR=1`, `TERM=dumb` или перенаправление вывода в файл дают обычный текст. Вывод самого роутера
и UART-логи никогда не раскрашиваются.

**Полноэкранный режим (TUI)** — режим по умолчанию: интерфейс на весь терминал — то же меню, что в консоли
(разделы «Главное», «Портирование», «Эксперт»), лог UART и событий всегда внизу экрана, подтверждения
в отдельном окне. Удобно по SSH, на Raspberry Pi и других Linux без графики; нужен терминал не меньше
80×24.

```
./UrsidoRescue-linux-arm64
UrsidoRescue.exe --lang ru
UrsidoRescue.exe --console      # прежнее текстовое меню
```

Справа от меню — что делает выбранный пункт, что для него нужно и какой риск. Вопросы «да/нет» и короткие
варианты — кнопками (← → и Enter), списки (COM-порт, профиль) — стрелками; ввести ответ вручную тоже можно.
Горячие клавиши работают и в русской раскладке (а/ь/ы/з/й), и через F-клавиши. В разделе «Эксперт» TUI
нет повторной «Диагностики» — она в «Главном». Пока операция не идёт, лог может сжиматься до 3 строк, чтобы
описание пункта помещалось на 80×24; во время операции он снова занимает около трети экрана. После операции
на экране — её итог и ID сессии, полный путь к каталогу логов — в логе.

| клавиша | действие |
|---|---|
| ↑ ↓, ← → / Tab | выбор пункта и раздела; в диалоге — выбор варианта |
| Enter | запустить пункт; ответить в диалоге |
| p (з), F4 | выбрать и подключить UART-порт (или отключить) |
| s (ы), Ctrl+C | СТОП во время операции — решает ядро (второй Ctrl+C за 3 с — принудительный выход) |
| PgUp / PgDn, End | прокрутка лога, к новым строкам |
| f (а), F2 | фильтр лога: всё / UART / события |
| m (ь), F3 | лог крупно |
| l (д) | язык: русский / английский |
| q (й), F10 | выход (когда операция не идёт) |

В бегущем логе внизу нет времени — только события и вывод UART (вывод роутера — салатовым, ошибки —
бордовым, метки этапов вроде `[XMODEM]` — янтарным). Время остаётся в файлах логов сессии и видно в панели
операции отдельной бледной колонкой.

UART-терминал, UART Shell и «RAM U-Boot и prompt» открываются на весь экран, как в консоли; после выхода
из них TUI возвращается. `NO_COLOR` выключает цвета.

**Командная строка:**

| команда | что делает |
|---|---|
| `--version` | печатает версию |
| `--selftest` | самопроверка: закреплённые SHA256 payloads, заголовки FIP, allowlist probe, CRC XMODEM, парсеры. `SELFTEST PASS` / `SELFTEST FAIL: …` |
| `probe [флаги]` | Porting Collector без меню |
| `export [--input DIR] [--output DIR] [--redact]` | переупаковать bundle из уже собранного каталога probe (по умолчанию — последняя probe-сессия в `work/sessions/`, старые `work/probe-*` тоже находятся) |

Флаги `probe`:

| флаг | смысл |
|---|---|
| `--uart PORT` | порт (`COM6`, `/dev/ttyUSB0`). Можно опустить: `probe` ищет порты так же, как меню (на Windows — `QueryDosDeviceW`). Ни одного порта — ошибка с кодом 2; ровно один — выбирается автоматически; несколько — печатается нумерованный список, код выхода 2, нужно повторить команду с `--uart PORT` |
| `--output DIR` | каталог данных probe (по умолчанию новая сессия `work/sessions/<дата>-<время>-probe-<hex>/`) |
| `--uboot-only` / `--linux-only` / `--no-linux` | ограничить среды (первые два взаимоисключающие) |
| `--bootrom` | ответить на `Press x` и проверить `C` от XMODEM |
| `--ram-uboot md\|mf` | «кирпич» Nokia: загрузить RAM U-Boot UrsidoRescue и исследовать через него |
| `--timeout 5m` | общий таймаут |
| `--sample 4k\|64k` | размер сэмпла начала каждого раздела |
| `--linux-user U --linux-password P` | учётные данные, если Linux спросит логин |
| `--stock-lan-assist` | stock Nokia MD/MF: получить актуальные реквизиты через Web `192.168.1.1` и войти по UART с проверкой UID 0 ([подробно](#stock-login)); FTP не включает |
| `--stop-key S` | особая клавиша остановки автозагрузки (например `tpl`) |
| `--wake` | устройство уже работает: разрешить один Ctrl-C |
| `--redact` | маскировать MAC/серийники в текстах, бинарные файлы не класть |
| `--no-export` | не создавать zip |
| `--ubi-attach` | ADVANCED, **не только чтение**: разрешить `ubi part` |
| `--unsafe` | ничего не ослабляет: probe остаётся только-чтение, печатается предупреждение |

Коды выхода `probe`: `0` ок, `1` ошибка, `2` UART недоступен, `3` BootROM не найден, `4` U-Boot не
найден, `5` Linux недоступен, `6` профиль неполный, `7` заблокировано нарушение безопасности.

Примеры:

```
UrsidoRescue.exe probe --uart COM6
./UrsidoRescue-linux-amd64 probe --uart /dev/ttyUSB0 --output ./probe
./UrsidoRescue-linux-amd64 probe --uart /dev/ttyUSB0 --ram-uboot md
./UrsidoRescue-linux-amd64 export --redact
```

## 7. Файлы и логи

| путь | что там |
|---|---|
| `work/sessions/<дата>-<время>-<операция>-<hex>/` | **сессия**: каждая операция меню работает в своей (probe-пункты — в общей, пока не выбран «N») |
| `…/uart.log` | полный сырой UART-лог операции (раньше `work/recovery-*`, `term-*`, `shell-*.uart.log`) |
| `…/session.log` | события и вопросы программы с временем (ответы не пишутся — там могут быть пароли) |
| `…/operations.jsonl` | структурированный журнал: начало и итог операции, каждая команда U-Boot с кодом возврата и временем, подтверждения, созданные файлы |
| `…/errors.log` | ошибки |
| `…/session.json` | вид операции, версия, интерфейс, время, итог (`success` / `cancelled` / `failed`), operation ID |
| `…/stock-<время>/`, `…/physical-<время>/` | временная нарезка образа на части (пункты 1 и 3) |
| probe-сессия | дополнительно данные Porting Collector: `transcript.jsonl`, `uboot/`, `linux/`, `flash/`, `dt/`… |
| `UrsidoRescue-support-<время>.zip` | пакет логов для отчёта (пункт 6) |
| `ursus-probe-<vendor>-<model>-<soc>-<время>.zip` | porting bundle |

Каталоги `stock-*` и `physical-*` внутри сессии занимают столько же, сколько исходный образ (до 256 МиБ);
после успешного восстановления их можно удалить. Файлы старых версий в `work/` (`*.uart.log`, `probe-*`)
по-прежнему попадают в пакет логов и находятся командой `export`.

## 8. Если что-то пошло не так

Программа работает по принципу **fail-closed**: при любой неясности она останавливается и пишет
`[STOP] <причина>`. После остановки никаких новых команд записи не отправляется.

| сообщение | что делать |
|---|---|
| `тайм-аут ожидания BootROM XMODEM` | Проверьте TX/RX (поменяйте местами), GND, что Reset зажат **до** подачи питания, что выбран правильный порт |
| `UART определил AN758x, но выбран профиль …` | Выберите правильный профиль или Auto |
| `… SHA256 mismatch` / `size … != pinned` | Файлы в `payloads/` повреждены или заменены — распакуйте релиз заново |
| `XMODEM блок N не подтверждён после 8 попыток` | Помехи на линии/плохой контакт/длинный провод. Перезапустите с шага BootROM |
| `BootROM подтвердил отмену XMODEM … (CAN CAN)` | Приёмник сам прервал передачу. Перезапустите с шага BootROM |
| «Все XMODEM-блоки подтверждены, но EOT ACK не пришёл…» | Это не ошибка: программа ждёт следующий этап. Стоп будет только если он не появится |
| `автозагрузка ушла в Linux до prompt` | RAM U-Boot не успел остановиться. Повторите; убедитесь, что используется встроенный RAM FIP |
| `до prompt замечена разрушительная автозагрузка` | Стоп по безопасности. Сохраните лог и сообщите разработчикам |
| `в геометрии MTD нет маркера …` | NAND не опознан RAM U-Boot'ом или это не MD/MF. Сделайте диагностику (пункт 5) и пришлите лог |
| `На ПК не найден IPv4 192.168.1.x` | Настройте статический `192.168.1.254/24` на Ethernet |
| `TFTP не прошёл после 3 попыток: …` | Кабель в LAN-порту? Брандмауэр пропускает UDP 1069? Адрес ПК точно `192.168.1.x`? В скобках — причина последней попытки (`TFTP RRQ timeout` — запрос не дошёл до ПК) |
| `не удалось восстановить U-Boot prompt после сетевой ошибки` | U-Boot перестал отвечать. Сохраните лог; начните заново с BootROM |
| `[WARN] stock LAN assist не сработал: stock LAN assist timed out` | Web роутера не ответил за 90 с. Кабель в LAN2/LAN3, ПК в `192.168.1.x`, лишние адаптеры выключены? Если пароль Web-администратора менялся — `URSIDO_STOCK_WEB_PASSWORD`. Probe после этого спросит логин вручную |
| `stock Web model "…" is not a supported XG-040G-MD/MF` | Stock assist работает только с Nokia XG-040G-MD/MF. Введите логин вручную или `--linux-user` |
| `[WARN] UART login получен без UID 0…` | Вход есть, но не root. Диагностика идёт с текущими правами; для полной — ответьте `y` на вопрос о включении FTP, если он был |
| `bad-блок в критичной области стока …` | Автоматическое восстановление стока на этом экземпляре NAND небезопасно. Нужен ручной анализ |
| `BL2 в бэкапе начинается с … OpenWrt preloader` | Это не заводской бэкап, а снятый после перепрошивки |
| `CRC после записи не совпал` | Запись не подтвердилась. BL2 при этом ещё не тронут (он всегда последний) — можно повторить с начала |

Для отчёта: главное меню → **6**, приложите `UrsidoRescue-support-*.zip` и опишите, что делали.
Перед публикацией просмотрите логи на предмет MAC/серийников.
