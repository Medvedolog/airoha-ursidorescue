# Проверка на железе: TUI, рамка UART, выбор путей, установка UrsusBoot

Протокол для первого Windows-теста сборки `404b3b5` и новее (**CI PASS / HW PENDING**).
Нужны Windows 10/11 с Windows Terminal, Nokia XG-040G-MD или MF, UART и LAN.
Шаги 1–7 **не пишут во flash**; шаг 8 — запись, и только после того, как 1–7 прошли.

Сборку запускать двойным щелчком или из Windows Terminal (TUI по умолчанию). После каждого шага
сессия лежит в `work/sessions/`; для сценариев с устройством нужен её `uart.log`.

| # | Сценарий | Как | Ожидается |
|---|---|---|---|
| 1 | Рамка консоли | Эксперт → Прозрачная UART-консоль; порт выбрать в диалоге TUI; Enter, вставка строки (Ctrl+V / правая кнопка), Ctrl+Q | Шапка «UrsidoRescue │ COMx ● │ UART 115200 8N1 │ RAW │ LOG ●», плашка, строка клавиш внизу; ввод и вставка уходят в роутер; вывод прокручивается между полосами; Ctrl+Q — снова TUI без мусора на экране |
| 2 | Alternate screen | в Linux на роутере (UART-консоль) запустить `top` (или `vi`, `less`), выйти `q` / `:q` | при входе рамка исчезает и программа занимает весь экран; после выхода рамка на месте и **приглашение видно** |
| 3 | U-Boot bootmenu | включить роутер при открытой консоли, дойти до bootmenu (если в прошивке есть), выбрать пункт / выйти | меню рисуется на весь экран без рамки; после выхода из меню (курсор снова показан) рамка возвращается; дальнейший вывод загрузки виден |
| 3a | Обычный `clear` | в shell роутера `clear` | рамка **не** исчезает; приглашение — в первой строке области вывода, под шапкой |
| 4 | Ширина окна | при открытой консоли растянуть Windows Terminal **только по ширине**, затем нажать Enter | после следующего вывода устройства шапка и строка клавиш перестроены на новую ширину |
| 5 | Обзор: файл и каталог | Главное → Восстановление заводской Nokia; `*` — выбрать файл; повторить, `**` — выбрать каталог. Отдельно: путь с кириллицей; отмена в окне | окна проводника открываются поверх консоли; путь (и кириллица) возвращается верно; после «Отмена» вопрос задаётся снова, программа не падает |
| 6 | Каталог бэкапа | `**` → каталог, где есть `mtd16.bin.gz` (остальные mtd — не обязательно все) | каталог принят без выбора самого файла; в логе «файлы бэкапа mtd0..mtd16: есть N/17; источник восстановления=mtd16…» |
| 7 | Недавние пути | дойти до ошибки (например неверный путь или отказ в подтверждении), снова запустить тот же пункт | первым вариантом стоит последний путь; Enter его выбирает |
| 8 | Установка UrsusBoot | только после 1–7: Эксперт → Установка UrsusBoot (UART) на **MF со стоком**; дойти до подтверждения `INSTALL URSUSBOOT` | этапы 1/6…4/6 в шапке и панели; план чтения «MF · сток · … запись ещё НЕ началась»; бэкап `ursusboot/bootarea-before.bin` и кандидат в сессии. Первый раз — ввести **не ту** фразу: запись отменяется. Второй раз — настоящая установка: блоки + итоговая сверка 6/6, reset, UrsusBoot грузится |

**Что приложить к отчёту:** номер сборки, какие шаги прошли, для 2, 3 и 8 — `uart.log` сессии;
для 8 — `bootarea-before.bin`, `bootarea-target.bin` и строки `method=…`, `source/target SHA256`
из лога. Результат записать в CHANGELOG как **HW PARTIAL / PASS** с номерами шагов.
