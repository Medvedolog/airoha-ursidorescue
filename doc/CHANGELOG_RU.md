## 0.2.0-test9 — 2026-09-24

Статус: simulation PASS / HW PARTIAL. Проверка test8 на Windows/OpenWrt подтвердила обычный ввод
и живой вывод UART, но показала, что пейджер резал полноэкранные программы вроде BusyBox `top`.

- Пейджер Ctrl+P работает только для обычного построчного вывода.
- Полноэкранные ANSI/TUI-потоки распознаются по последовательностям «курсор домой», «очистка
  экрана», «альтернативный экран»; пейджер сразу сбрасывает очередь и выключается.
- Распознавание работает, даже если CSI-последовательность разорвана между двумя чтениями.
- Цветной вывод (SGR) и простая очистка строки TUI-режим не включают.
- `top`/`vi`/`less` сохраняют свою модель экрана; Ctrl+P можно снова включить для `ps`, `dmesg`,
  логов.
- Ctrl+C и Ctrl+Z явно передаются в роутер как `0x03` и `0x1A` в обоих режимах ввода, включая
  Windows `KEY_EVENT_RECORD`.
- Регрессионные тесты на всё перечисленное.

## 0.2.0-test8 — 2026-09-24

Статус: simulation PASS / HW PARTIAL. В test7 на Windows были видны Ctrl+P/Ctrl+Q, но обычные
клавиши и Enter могли теряться в новом raw-пути консоли.

- Ввод в терминале на Windows — через `ReadConsoleInputW` + `KEY_EVENT_RECORD` вместо байтового
  чтения `os.Stdin` в режиме `VIRTUAL_TERMINAL_INPUT`.
- Enter, Backspace, печатные ASCII, стрелки, Home/End/Delete переводятся явно; стрелка становится
  одной целой ANSI-последовательностью до записи в UART.
- Ctrl+Q, Ctrl+P, Ctrl+C, Ctrl+D, Ctrl+] переводятся локально.
- Не-латинский Unicode доходит до ASCII-фильтра и надёжно отклоняется с предупреждением о раскладке.
- `VIRTUAL_TERMINAL_INPUT` на stdin выключен; QuickEdit остаётся для буфера обмена.
- Linux без изменений. Тесты на Enter/стрелки/Ctrl-клавиши Windows и блокировку кириллицы.

## 0.2.0-test7 — 2026-09-24

Статус: simulation PASS / HW PARTIAL. На OpenWrt выяснилось, что старый UART Shell (Эксперт 6)
читал консоль по байту и опрашивал порт каждые 250 мс: стрелки рвались, ввод отставал почти на
секунду.

- Эксперт 6 использует тот же низколатентный raw-движок, что и Эксперт 1; отдельной побайтовой
  реализации больше нет.
- Опрос порта в интерактиве — 20 мс вместо 200/250 мс.
- Ввод и вставка пишутся кусками; ANSI-стрелки не рвутся.
- Ctrl+Q и Ctrl+] — выход из UART Shell.
- Команды — только ASCII: байты ≥ 0x80 блокируются локально с предупреждением. XMODEM не затронут.
- Ctrl+P — локальный пейджер по высоте окна; на паузе UART продолжает читаться и логироваться,
  Enter — следующая страница; очередь не более 4 МиБ.

## 0.2.0-test6 — 2026-09-24

Статус: simulation PASS / HW PARTIAL. Интерактивный UART-терминал впервые работал на реальном
OpenWrt; исправлены найденные проблемы Windows. Probe и запись — HW HOLD.

- Windows показывает только реально существующие COM-порты (`QueryDosDeviceW`) с выбором по номеру;
  ручной ввод `COM<n>` остался.
- Запись в порт на Windows больше не вызывает `FlushFileBuffers` после каждой записи — ушла
  задержка ввода почти в секунду.
- QuickEdit в raw-режиме остаётся включённым — выделение/копирование/вставка снова работают.
- Ctrl+Q — локальный быстрый выход, в роутер не отправляется.
- Тесты: стрелка уходит одной записью, Ctrl+Q остаётся локальным.

## 0.2.0-test3 — 2026-09-24

Исправления по ревью перед первым probe на железе.

- `ubi part` убран из строгого probe: attach UBI может записывать (auto-resize, fastmap).
  Геометрия UBI разбирается офлайн из заголовков EC/VID; attach в U-Boot — отдельный ADVANCED-режим
  (`--ubi-attach`, пункт A), помечен как не read-only.
- Утечка идентичности: `macaddr` из `/etc/board.json` попадал в `profile.json`. Рекурсивный
  санитайзер теперь чистит профиль, отчёт и черновик; добавлены регрессионные тесты.
- Неизвестные устройства — пассивно: без Ctrl-C и команд, пока не виден баннер U-Boot/Linux;
  `--wake` разрешает один Ctrl-C, и команды U-Boot получают только известные приглашения.
- Внутренние служебные строки — фиксированные протестированные шаблоны (`probe/internal.go`).
- `--redact` обрабатывает и JSON-поля идентичности и не кладёт бинарные файлы в bundle.
- CI: сборка и тесты на каждый push, pre-release для тегов `v*`.
