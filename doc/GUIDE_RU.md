# Руководство оператора UrsidoRescue

[English version](GUIDE_EN.md) · [Оглавление](README.md) · версия 0.2.0-test10

## 0. Прежде чем начать

- Это **лабораторная UART-сборка**. Запись во flash на железе пока не прошла полный цикл проверки —
  см. [../STATUS.md](../STATUS.md). Работайте, только если понимаете, что делаете, и у вас есть
  бэкап.
- **Бэкап — главное.** Заводские MAC, серийный номер, GPON-данные и калибровки оптики невозможно
  восстановить без бэкапа (например, снятого MedveFlasher).
- Для чтения и диагностики (пункты 5, 7, эксперт 1/6) ничего не пишется во flash. Пункты 1–3 и
  эксперт 3/4 пишут — перед записью всегда требуется ввести фразу подтверждения.

## 1. Что понадобится

| что | зачем |
|---|---|
| USB-UART адаптер **3.3 В TTL** (CH340, CP2102, FT232 …) | консоль роутера, BootROM, XMODEM |
| 3 провода: **GND, TX, RX** | **VCC не подключать никогда** — роутер питается от своего блока |
| Ethernet-кабель ПК ↔ LAN-порт роутера | TFTP для больших файлов (пункты 1–4, эксперт 3–4) |
| Windows x64 или Linux x86_64 / arm64 | сама программа |
| Бэкап или образ | в зависимости от пункта: `mtd16`, `.fip`, `.itb`, образ NAND 256 МиБ |

**Подключение UART:** TX адаптера → RX роутера, RX адаптера → TX роутера, GND → GND.
Параметры порта (программа выставляет их сама): 115200, 8N1, без управления потоком.

## 2. Установка

1. Скачайте `UrsidoRescue-<версия>.zip` со страницы Releases репозитория и распакуйте.
2. Проверьте целостность: `SHA256SUMS` внутри архива, `.zip.sha256` рядом с архивом.
3. Внутри:

```
UrsidoRescue-0.2.0-test10/
  UrsidoRescue.exe            Windows x64
  UrsidoRescue-linux-amd64    Linux x86_64
  UrsidoRescue-linux-arm64    Linux aarch64 (Raspberry Pi 4/5, ARM-ноутбуки)
  VERSION
  payloads/md/…               preloader и RAM FIP для XG-040G-MD
  payloads/mf/…               preloader и RAM FIP для XG-040G-MF
  STATUS.md  PROBE.md  SHA256SUMS
```

Программа ищет `VERSION` и `payloads/` рядом с собой (до трёх уровней вверх) или в текущем
каталоге. Не перемещайте бинарник отдельно от них. Рабочие файлы и логи создаются в `work/`.

**Linux:** доступ к порту обычно требует группы `dialout` (`sudo usermod -aG dialout $USER`,
затем перелогиниться) или запуска через `sudo`.

**Windows:** при первом запуске Защитник/SmartScreen может предупредить о неподписанном файле.
Для TFTP разрешите входящий UDP-порт **1069** в брандмауэре (или разрешите программе доступ к
частной сети, когда Windows спросит).

## 3. Сеть для TFTP

Нужна для пунктов 1–4 и эксперт 3–4.

- Назначьте Ethernet-адаптеру ПК статический адрес **`192.168.1.254`**, маска `255.255.255.0`
  (любой `192.168.1.x`, кроме `.1`, тоже подойдёт).
- Роутер в RAM U-Boot получит адрес **`192.168.1.1`**.
- Программа сама найдёт адрес `192.168.1.x` на ПК. Если не найдёт — попросит ввести его вручную.
- Встроенный TFTP-сервер слушает `UDP 1069` и отдаёт файл только адресу `192.168.1.1`.
- Wi-Fi лучше отключить, если он тоже в сети `192.168.1.0/24`.

## 4. Как ввести роутер в BootROM

Для всех операций с RAM U-Boot:

1. Выключите роутер.
2. Подключите UART, запустите нужный пункт в программе и дождитесь сообщения
   «Ожидание BootROM Press x / CCC».
3. **Зажмите Reset и подайте питание.** Держите Reset, пока в выводе не появится `Press x`
   (программа сама ответит `x`) и строка `CCC…`.
4. Дальше программа всё делает сама: preloader → FIP → приглашение U-Boot.

Если на экране **уже** `Press x to load BL31 + U-Boot FIP` и бегут `C` — ничего не перезагружайте:
программа поймёт, что preloader уже загружен, и отправит только FIP.

> Не путайте с recovery UrsusBoot: Reset, **зажатый до подачи питания**, — это BootROM Airoha;
> Reset, зажатый **после** старта (2 коротких + 3 длинных мигания), — это recovery-режим UrsusBoot.

## 5. Запуск

**Интерактивно:**

```
Windows:  двойной щелчок по UrsidoRescue.exe   (или из cmd/PowerShell)
Linux:    ./UrsidoRescue-linux-amd64
```

Язык спрашивается при старте. Задать заранее: `--lang ru|en` (в любом месте командной строки) или
переменная окружения `URSIDO_LANG=ru|en`. Все пункты меню описаны в [MENU_RU.md](MENU_RU.md).

**Командная строка:**

| команда | что делает |
|---|---|
| `--version` | печатает версию |
| `--selftest` | самопроверка: закреплённые SHA256 payloads, заголовки FIP, allowlist probe, CRC XMODEM, парсеры. `SELFTEST PASS` / `SELFTEST FAIL: …` |
| `probe [флаги]` | Porting Collector без меню |
| `export [--input DIR] [--output DIR] [--redact]` | переупаковать bundle из уже собранного каталога probe (по умолчанию — последний `work/probe-*`) |

Флаги `probe`:

| флаг | смысл |
|---|---|
| `--uart PORT` | порт (`COM6`, `/dev/ttyUSB0`). На Windows обязателен; на Linux можно опустить, если порт ровно один |
| `--output DIR` | каталог сессии (по умолчанию `work/probe-<время>`) |
| `--uboot-only` / `--linux-only` / `--no-linux` | ограничить среды (первые два взаимоисключающие) |
| `--bootrom` | ответить на `Press x` и проверить `C` от XMODEM |
| `--ram-uboot md\|mf` | «кирпич» Nokia: загрузить RAM U-Boot UrsidoRescue и исследовать через него |
| `--timeout 5m` | общий таймаут |
| `--sample 4k\|64k` | размер сэмпла начала каждого раздела |
| `--linux-user U --linux-password P` | учётные данные, если Linux спросит логин |
| `--stop-key S` | особая клавиша остановки автозагрузки (например `tpl`) |
| `--wake` | устройство уже работает: разрешить один Ctrl-C |
| `--redact` | маскировать MAC/серийники в текстах, бинарные файлы не класть |
| `--no-export` | не создавать zip |
| `--ubi-attach` | ADVANCED, **не только чтение**: разрешить `ubi part` |
| `--unsafe` | ничего не ослабляет: probe остаётся только-чтение, печатается предупреждение |

Коды выхода `probe`: `0` ок, `1` ошибка, `2` UART недоступен, `3` BootROM не найден, `4` U-Boot не
найден, `5` Linux недоступен, `6` профиль неполный, `7` заблокировано нарушение безопасности.

Примеры:

```
UrsidoRescue.exe probe --uart COM6
./UrsidoRescue-linux-amd64 probe --uart /dev/ttyUSB0 --output ./probe
./UrsidoRescue-linux-amd64 probe --uart /dev/ttyUSB0 --ram-uboot md
./UrsidoRescue-linux-amd64 export --redact
```

## 6. Файлы и логи

| путь | что там |
|---|---|
| `work/recovery-<время>.uart.log` | полный UART-лог операций с RAM U-Boot (пункты 1–5, эксперт 2–5) |
| `work/term-<время>.uart.log` | лог UART-терминала (эксперт 1) |
| `work/shell-<время>.uart.log` | лог UART Shell (эксперт 6) |
| `work/stock-<время>/` | `mtd16`, разрезанный на BL2 + части по 8 МиБ (пункт 1) |
| `work/physical-<время>/` | образ NAND, разрезанный на части (пункт 3) |
| `work/probe-<время>/` | сессия Porting Collector |
| `UrsidoRescue-support-<время>.zip` | пакет логов для отчёта (пункт 6) |
| `ursus-probe-<vendor>-<model>-<soc>-<время>.zip` | porting bundle |

Каталоги `stock-*` и `physical-*` занимают столько же, сколько исходный образ (до 256 МиБ);
после успешного восстановления их можно удалить.

## 7. Если что-то пошло не так

Программа работает по принципу **fail-closed**: при любой неясности она останавливается и пишет
`[STOP] <причина>`. После остановки никаких новых команд записи не отправляется.

| сообщение | что делать |
|---|---|
| `тайм-аут ожидания BootROM XMODEM` | Проверьте TX/RX (поменяйте местами), GND, что Reset зажат **до** подачи питания, что выбран правильный порт |
| `UART определил AN758x, но выбран профиль …` | Выберите правильный профиль или Auto |
| `… SHA256 mismatch` / `size … != pinned` | Файлы в `payloads/` повреждены или заменены — распакуйте релиз заново |
| `XMODEM блок N не подтверждён` | Помехи на линии/плохой контакт/длинный провод. Перезапустите с шага BootROM |
| `автозагрузка ушла в Linux до prompt` | RAM U-Boot не успел остановиться. Повторите; убедитесь, что используется встроенный RAM FIP |
| `до prompt замечена разрушительная автозагрузка` | Стоп по безопасности. Сохраните лог и сообщите разработчикам |
| `в геометрии MTD нет маркера …` | NAND не опознан RAM U-Boot'ом или это не MD/MF. Сделайте диагностику (пункт 5) и пришлите лог |
| `На ПК не найден IPv4 192.168.1.x` | Настройте статический `192.168.1.254/24` на Ethernet |
| `U-Boot не пингует ПК` | Кабель в LAN-порту? Брандмауэр? Адрес ПК точно `192.168.1.x`? |
| `TFTP RRQ timeout` | Брандмауэр блокирует UDP 1069; или U-Boot не видит сеть |
| `bad-блок в критичной области стока …` | Автоматическое восстановление стока на этом экземпляре NAND небезопасно. Нужен ручной анализ |
| `BL2 в бэкапе начинается с … OpenWrt preloader` | Это не заводской бэкап, а снятый после перепрошивки |
| `CRC после записи не совпал` | Запись не подтвердилась. BL2 при этом ещё не тронут (он всегда последний) — можно повторить с начала |

Для отчёта: главное меню → **6**, приложите `UrsidoRescue-support-*.zip` и опишите, что делали.
Перед публикацией просмотрите логи на предмет MAC/серийников.
